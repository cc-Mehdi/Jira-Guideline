## 📌 جیرا (Jira) چیست؟

**جیرا** یک ابزار مدیریت پروژه است که توسط Atlassian توسعه داده شده و برای **مدیریت تسک‌ها، پیگیری پیشرفت پروژه‌ها و همکاری تیمی** استفاده می‌شود. این ابزار در سه نسخه ارائه می‌شود:

- **نرم افزار جیرا (Jira Software)** (مناسب برای تیم‌های توسعه نرم‌افزار با قابلیت Scrum/Kanban)
- **مدیریت خدمات جیرا (Jira Service Management)** (برای مدیریت درخواست‌های IT و خدمات مشتریان)
- **مدیریت کار جیرا (Jira Work Management)ا** (برای مدیریت وظایف عمومی کسب‌وکار)

## 🏗 ساختار Jira

### 🔹 پروژه‌ها (Projects)
در Jira، تمامی تسک‌ها در قالب **پروژه‌ها** سازمان‌دهی می‌شوند. هر پروژه می‌تواند یک مدل مدیریت متفاوت داشته باشد، مانند:

- **سیستم زمان بندی Kanban** (برای کارهای پیوسته و بدون اسپرینت)
- **چهارچوب همکاری تیم چابک Scrum** (برای کارهای چابک در اسپرینت‌های زمان‌بندی‌شده)
- **فرایند Bug Tracking** (برای مدیریت و پیگیری باگ‌ها)

### 🔹 انواع Issue در Jira
**موضوع (Issue)** همان تسک‌هایی هستند که در Jira ثبت می‌شوند. انواع آن شامل:

- **نوع Epic** (یک ویژگی یا هدف کلی شامل چندین وظیفه)
- **نوع Story** (یک نیاز کاربر که باید پیاده‌سازی شود)
- **نوع Task** (یک وظیفه خاص)
- **نوع Sub-task** (یک بخش از یک Task بزرگتر)
- **نوع Bug** (مشکلات نرم‌افزاری که باید برطرف شوند)

### 🔹 بردهای Jira (Boards)
- **برد Kanban (Kanban Board)** برای تیم‌هایی که به دنبال جریان کاری پیوسته هستند.
- **برد Scrum (Scrum Board)** برای تیم‌های چابک که از **Sprint** استفاده می‌کنند.

## 🛠 نحوه استفاده از Jira

### 🔹 ایجاد یک Issue
1. وارد **Jira Project** موردنظر شوید.
2. روی **Create** کلیک کنید.
3. نوع Issue را انتخاب کنید (Task, Bug, Story, Epic).
4. **عنوان مناسب** و **توضیحات کامل** وارد کنید.
5. **شخص مسئول (Assignee)** را مشخص کنید.
6. **اولویت (Priority)** را تعیین کنید.
7. روی **Create** کلیک کنید.

### 🔹 پیگیری پیشرفت کارها
- **بخش Backlog**: لیستی از وظایف برنامه‌ریزی‌شده
- **بخش Sprint**: مجموعه‌ای از وظایف که در یک دوره زمانی مشخص انجام می‌شوند
- **وضعیت های To Do, In Progress, Done**: وضعیت‌های مختلف یک تسک

### 🔹 به‌روزرسانی وضعیت تسک‌ها از طریق برد پروژه (Project Board)
برای تغییر وضعیت یک Issue:
1. به **برد پروژه** بروید.
2. تسک (Issue) موردنظر را بکشید و در ستون جدید رها کنید.
3. گزارش کار (work log) بگذارید تا هم‌تیمی‌ها در جریان تغییرات باشند.

## 📑 روند ثبت گزارش کار در سازمان

### 🔹 مراحل ثبت گزارش کار:
1. **تغییر وضعیت تسک**
   - وضعیت تسک باید بر اساس پیشرفت کار تغییر کند، برای مثال: `To Do`, `In Progress`, `Code Review`, `Done`.
2. **اختصاص دادن (Assign) کردن تسک به شخص مسئول**
   - پس از انجام تغییر وضعیت، تسک به شخصی که باید روی آن کار کند اختصاص داده می‌شود.
3. **ثبت گزارش کار**
   - مدت زمان صرف شده برای انجام کار ثبت شود.
   - توضیحات دقیق از کار انجام‌شده نوشته شود.
   - در صورت نیاز، تصاویر از خروجی یا کدهای مربوطه پیوست شود.
   - لینک **Git Commit** مربوط به این کار اضافه شود.

## 🔄 مدیریت Workflow در Jira
**گردش کار (Workflow)** تعیین می‌کند که یک Issue از چه مراحلی عبور کند.

🔹 وضعیت‌های پیش‌فرض:
- **وضعیت To Do**: وظایف برنامه‌ریزی‌شده
- **وضعیت In Progress**: وظایفی که در حال انجام هستند
-  **وضعیت In Review**: بررسی خروجی توسط تیم
- **وضعیت Code Review**: بررسی کد توسط تیم
- **وضعیت Done**: وظایفی که به پایان رسیده‌اند

## 🔗 ادغام Jira با GitLab
**جیرا (Jira)** را می‌توان با GitLab ادغام کرد تا وضعیت Issueها به‌طور خودکار با Merge Requestها هماهنگ شوند.

**مراحل تنظیم اتصال Jira و GitLab:**
1. به **GitLab Project Settings** بروید.
2. از بخش **Integrations** گزینه **Jira** را انتخاب کنید.
3. آدرس URL و API Token مربوط به Jira را وارد کنید.
4. **قسمت (Enable integration)** را فعال کنید.

✅ بعد از این تنظیمات، می‌توان **Issue Keys** (مانند `PROJ-123`) را در کامیت‌ها و Merge Requestها استفاده کرد تا به‌طور خودکار در Jira ثبت شوند.


## 🚀 بهترین روش‌ها در استفاده از Jira
✔ تسک‌ها را با **عنوان دقیق و توضیحات شفاف** ثبت کنید.  
✔ از **Labels** و **Components** و **Versions** برای سازمان‌دهی بهتر استفاده کنید.  
✔ در کامنت‌ها از **@mention** استفاده کنید تا افراد مرتبط مطلع شوند.  
✔ از **Automation Rules** برای ساده‌سازی فرآیندها استفاده کنید.  
✔ گزارش‌های دوره‌ای از **Burndown Chart و Velocity** برای بررسی عملکرد تیم بگیرید.
